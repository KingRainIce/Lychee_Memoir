# 深大记忆（SZU Memoir）— 产品需求说明

> 本文档随讨论迭代更新；变更记录在文末「修订记录」。

---

## 1. 项目概述

**项目名称**：深大记忆  
**形态**：智能体网站（Web）  
**核心**：以「校区地图 × 时间轴 × 内容（校园事件 / 校友帖子）」组织信息与检索，辅以右侧可折叠的 AI 对话（RAG）。

---

## 2. 用户与场景

- 用户可指定**校区**（多校区时切换）；**首次进入站点须完成校区选择**（可记入本地，避免每次打扰）。
- 主要场景：按时间在地图上看「发生过什么」；在「最新时间」看校友动态；用自然语言检索事件与帖子。
- **呈现原则**：地图上的内容一律按**地点**（在校园平面图 / 地图上的位置）组织展示；对内可保存经纬度等字段，**不对用户强调「经纬度」叙事**。

---

## 3. 功能需求

### 3.1 地图展示

| 项 | 说明 |
|----|------|
| 校区范围 | 用户所选校区在地图上为**彩色**正常显示。 |
| 外围区域 | 学校周围 / 校区外为**灰色**（弱化校外，聚焦校内）。**当前阶段可暂缓**：默认平面图模式下以外围灰/彩色对比为**后续迭代**，不阻塞主线。 |
| 地点绑定 | 事件与帖子均须绑定**地图上的地点**（与平面图归一化坐标或校内位置方案一致）；在对应地点展示气泡/卡片。 |

### 3.2 时间线（页面下方）

| 项 | 说明 |
|----|------|
| 形态 | 类似**尺子刻度**的时间轴，置于页面下方。 |
| 交互 | 鼠标可**左右拖动**时间线以改变「当前时间上下文」。 |
| 视觉效果 | 拖动位置及**邻近刻度向上突起**；距当前选中时刻越远，突起**越小**（参考 **macOS 程序坞** 的缩放/层次效果）。 |
| 时间精度 | **校园历史事件**：时间轴与筛选须能精确到**月**（年-月）。**「最新」模式下的帖子**：发布时间须精确到**秒**。 |
| 与地图联动 | 时间变化时，地图上展示的内容随**当前时间过滤规则**更新（见 3.3、3.4）。 |

### 3.3 校园事件（历史时间轴）

| 项 | 说明 |
|----|------|
| 展示 | 在地图上以**冒泡卡片**形式展示当前时间相关事件的**摘要**与**事件图片**。 |
| 位置 | 卡片出现在事件在地图上的**对应地点**（非对用户展示「经纬度」概念）。 |
| 时间 | 事件业务时间精确到**月**即可。 |
| 详情 | **点击卡片**后展示**全文**（完整事件内容）。 |
| 数据加载 | **仅加载与当前历史时间轴所选时间上下文相匹配的事件**（月精度：例如不提前拉取整段历史的全量事件，而以当前选中月及约定规则过滤，细则见 §4）。 |

### 3.4 校友帖子（「最新」时间）

| 项 | 说明 |
|----|------|
| 触发条件 | 时间线处于**最新**（当前时刻 / 时间轴右端「现在」）时启用。 |
| 展示 | 在地图上**实时**显示校友发布的帖子（与地点绑定，在对应位置冒泡）。 |
| 时间 | 帖子**发布时间精确到秒**（存储、排序、展示一致）。 |
| 实时性 | 新帖在审核通过后应能持续出现在地图上（WebSocket 等）。 |
| 数据加载与聚合 | **最新模式**下，帖子数据源为已通过审核的帖子，且**默认仅加载「用户本次登录所在自然日的 0 点 0 分 0 秒」至当前时刻**范围内的帖子（突出当日动态；若需全量历史另议）。**同一地图地点**（同一平面坐标或按规则聚类为同一点）在地图上**只占用一个入口**：多个帖子以**堆叠/重叠卡片**形式表现，并以数量提示（如 **「10+」**）表示该地点下帖数。 |

### 3.5 AI 聊天与 RAG（屏幕右侧）

| 项 | 说明 |
|----|------|
| 布局 | 屏幕**右侧**提供 **AI 聊天框**。 |
| 可见性 | 支持**隐藏**与**展开**（可折叠侧栏）。 |
| 检索范围 | 在**「最新」模式**下，检索可同时覆盖**历史校园事件**与**帖子**（新老内容均可进入向量检索）。 |
| 回答与结果展示 | **不得**将向量检索到的正文片段**改写、糅合**进模型的一段「总结式回答」里作为主呈现。检索到的内容须在对话区域内以**卡片**形式**直接展示**：**左侧**为条目配图（事件图 / 帖子图或占位），**右侧**为本次向量检索命中的**文本切片**（**严格为检索块本身**，不是全文、也不是帖子简介/摘要）。 |
| 分类 | 卡片分区或分组展示：**校园事件**、**帖子**，来源类型一目了然。 |
| 引用与溯源 | 用户点击某条检索结果时，交互与 **3.5** 中卡片一致（同结构：左图右切片）；可再提供进入**详情 / 地图定位**的扩展操作（可选）。 |

---

## 4. 全局状态与联动（逻辑摘要）

- **校区**：影响地图范围、数据过滤；须与多校区配置（含 **B 校区** 等）前后端一致；B 校区平面图与边界标注由运营补全后，开发侧须同步配置与种子数据。
- **当前时间（时间轴）**：历史侧精确到**月**；「最新」侧进入实时帖子模式，帖子时间到**秒**。
- **数据加载**：历史事件按当前时间轴上下文**按月**拉取/过滤；最新帖子按 **§3.4** 的「登录日 0 点起」窗口 + **同地点聚合**规则。
- **地图与 AI**：AI 检索结合当前校区、当前时间模式（历史月 / 最新）传参；结果以**卡片 + 切片**为主，不以长文复述检索正文。

---

## 5. 数据与内容

- **校园事件**：标题、时间（**到月**）、**地图地点**、摘要、正文、配图等。
- **校友帖子**：作者 / 登录、正文、**媒体**（支持发帖区**拖入图片/文件**上传或等价交互）、**地图地点**、发布时间（**到秒**）；审核与合规策略。
- **地点与地址**：用户以**在地图上选点**为主表达「在哪里」；**不将「输入文字地址自动变成地图上的点」作为本期必做能力**（若后期需要再单独立项，涉及第三方地理服务与合规）。
- **RAG**：事件库、帖子库分源检索；**展示以向量切片卡片为准**（见 3.5）。

### 5.1 给非开发读者的说明

- **「地理编码」**：指把「深圳市××路」这类文字自动算成地图坐标。当前产品**不要求**先做这件事，**点在地图上**即可。
- **「数据库迁移 / Alembic」**：指表结构变更时的**版本化管理**，像给数据库表做「改版记录」，方便上线升级，**与最终用户使用的功能无直接关系**。

---

## 6. 技术方向备忘（非最终选型）

- 地图：如 MapLibre / Mapbox + 自定义样式；校区边界可用 GeoJSON；**多校区**须与平面图资源、边界数据同步（含 **B 校区**）。
- 时间轴：自研 UI + 坞式缩放；刻度与状态须支持**年-月**与「最新」二态。
- RAG：向量检索；**对话区以卡片展示切片**；模型可用于极短引导语（若有），但**检索主体不以揉入长回答的形式替代**。

---

## 7. 建议的迭代顺序（参考）

1. 时间轴月精度、帖子秒精度与接口字段；历史事件按月加载、最新帖子按登录日窗口与同地点聚合。  
2. 多校区（含 **B 校区**）配置、平面图与 `campus_geo` 对齐；首次进入选校区。  
3. AI 侧卡片化展示（左图右切片）与「不糅合正文」的接口与 UI。  
4. 发帖拖入图片与存储链路。  
5. 外围灰视觉、地理编码、合规模块等按排期插入。

---

## 8. 前端实现状态（简要）

- 工程目录：`frontend/`（Vite + React + TypeScript + MapLibre）。  
- **默认底图**：彩色 **平面图模式**；标注工具与 `annotations.json` 流程见 `docs/地图与数据.md`。  
- **已部分实现**：时间轴（当前多为年粒度，**待升为月**）、事件/帖子 API、审核、WebSocket、RAG 分栏文本引用（**待改为 3.5 卡片 + 切片**）、顶栏校区选择（**待首次进入必选**与 **B 校区** 全链路）、发帖**待支持拖入图片**、帖子时间**待到秒**与 **§3.4 加载/聚合** 策略。  
- **暂缓**：平面图外围灰与街图「校外灰」的视觉统一（见 3.1）。  
- 后端：`backend/` + `docker-compose.yml`。
